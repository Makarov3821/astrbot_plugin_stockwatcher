# StockWatcher 私人盯盘助理

面向单人使用的 AstrBot 插件。首先支持美股，免费数据优先、接受延迟，提供持仓账本和按需 AI 决策辅助。

当前 `v0.6.0` 是第 01～10 步的安装测试修订版：持仓/关注、成交账本、个人引导、证据化 AI 研判、条件监控、收盘日报和按需多角色研究。不自动下单。真实 AstrBot、数据账户和平台仍需安装后验收，详见 [验证记录](docs/VALIDATION.md)。

**首次安装请看 [安装与试用步骤](docs/INSTALL_TEST.md)**。开发目录的 `dist/` 提供 ZIP 和 SHA-256 校验文件；包内含源提交与逐文件哈希清单。ZIP 不含 AstrBot 本地软链接、虚拟环境、凭证或个人数据库。

## 安装

目标环境：Python 3.12+、AstrBot `>=4.28.2,<5`，建议先用 `4.29.1` 或更新的兼容版本。注册/指令审查参考 `fc6b326`，入口白名单实现前已更新并核对 master `0cd42bd` 的会话和消息类型接口；整个声明版本范围尚未做运行验证。

1. 在 AstrBot 插件管理中通过仓库地址 `https://github.com/Makarov3821/astrbot_plugin_stockwatcher` 安装；也可将本仓库置于 `data/plugins/astrbot_plugin_stockwatcher/`。
2. 让 AstrBot 安装 `requirements.txt` 中的依赖；也可在其 Python 环境执行 `pip install -r requirements.txt`。
3. 在需要授权的私聊发送 `/盯盘 入口`，将返回的完整 UMO 添加到插件设置的「消息入口白名单」。至少一项，可添加多个；保存并重载后再发送 `/盯盘 帮助`、`/盯盘 状态`。也支持 `/stockwatch` 别名。
4. 行情需要 Alpaca 凭证；账本无需行情或模型配置即可使用。
5. 发送 `/盯盘 开始` 分步设置个人偏好；用 `/盯盘 开始 MU` 只补充个股缺少的期待。

插件数据存于宿主的 `data/plugin_data/astrbot_plugin_stockwatcher/stockwatcher.sqlite3`，不会写入插件源代码目录。业务指令仅接受白名单中的私聊入口，宿主访问控制继续叠加生效。未配置至少一个合法入口时，业务和自动任务停用；只读 `/盯盘 入口` 仅显示本会话标识，不自动授权。

白名单字段为 `allowed_origins`，按 `平台实例ID:FriendMessage:会话ID` 精确匹配，支持多个平台和多个私聊入口。请复制 `/盯盘 入口` 的输出，不使用昵称、单独的 QQ 号或通配符。所有获准入口均可读写同一份个人数据。旧版升级也须先补齐白名单；提醒接收会话必须仍在白名单内。[入口白名单说明](docs/ACCESS_CONTROL.md)。

## 配置与行情验证

在插件配置页填写 `alpaca_key_id`、`alpaca_secret_key`，或在 AstrBot 进程环境中设置 `APCA_API_KEY_ID`、`APCA_API_SECRET_KEY`。不要把凭证发给聊天机器人。配置页的遮罩只影响显示，不加密配置文件。

`alpaca_account_mode` 选择凭证所属的 `paper` 或 `live`；仅决定只读交易日历和标的资料的接口，不调用下单接口。展示时区默认 `Asia/Shanghai`，市场时段使用 `America/New_York` 自动处理夏令时与提前收市。

行情使用显式 `feed=sip` 的历史接口，免费查询默认截止当前时间之前 16 分钟。不是免费实时 SIP 推送。分钟数据只保留完整的常规时段分钟；供应商日线标记为 `provider_daily`，其是否包含盘前盘后尚需实测，不假称纯常规日线。日线剔除尚未结束的交易日。

可用命令：

```text
/盯盘 行情 MU
/盯盘 行情 MU 分钟
/盯盘 行情 MU 日线 all
/盯盘 日历 2026-11-27
/盯盘 诊断 MU
/盯盘 缓存 MU
```

`raw` 为原始价，`split`/`dividend`/`all` 为供应商的相应调整口径。不同口径单独存储，每次保存完整查询快照，不把不同日期生成的调整历史直接拼接。行情成交量以股计，价格以 USD 计。

`缓存` 显示原抓取时间并明确未联网刷新；请求失败不会悄悄将旧缓存当作新行情。手动查询日线约覆盖 550 个自然日，分钟约覆盖最近 7 个自然日；没有数据时不推断停牌原因。

不依赖 AstrBot 的只读诊断入口：

```bash
uv --cache-dir /tmp/stockwatcher-uv-cache venv .venv
uv pip install --python .venv/bin/python --cache-dir /tmp/stockwatcher-uv-cache -r requirements.txt
read -r -p "Alpaca Key ID: " APCA_API_KEY_ID
read -r -s -p "Alpaca Secret Key: " APCA_API_SECRET_KEY
export APCA_API_KEY_ID APCA_API_SECRET_KEY
.venv/bin/python -m stockwatcher.probe --symbol MU
unset APCA_API_KEY_ID APCA_API_SECRET_KEY
```

模拟凭证默认 `paper`，真实账户凭证可设置 `STOCKWATCHER_ACCOUNT_MODE=live`。诊断只访问标的资料、日历与历史行情，不访问持仓/订单，不输出凭证。它使用临时数据库，退出后删除；插件内诊断会将成功查询存入插件缓存。

退出码：`0` 表示接口与字段检查得到非空结果，`1` 表示缺少足够行情，`2` 表示未配置、参数或接口错误。成功不等于已验证长期稳定性、历史完整性或所有复权事件。

## 偏好、材料与 AI 分析

```text
/盯盘 开始
/盯盘 回答 账户=现金
/盯盘 回答 采用默认
/盯盘 引导 暂停
/盯盘 引导 继续
/盯盘 开始 MU
/盯盘 设置 MU 周期=180 目标=200 目标期限=2027-04-01 理由="等待业绩改善"
/盯盘 设置 MU 允许加仓=否
/盯盘 设置 MU 周期=继承
/盯盘 大盘预期 中性 期限=2026-12-31 基准=SPY
/盯盘 材料 更新 MU
/盯盘 材料 列表 MU
/盯盘 分析 MU
/盯盘 分析 MU 缓存
/盯盘 分析记录 MU
/盯盘 报告 1
/盯盘 目标
/盯盘 目标 采用 1
```

以上价格和日期仅为指令示例。引导草稿确认后生效，可跳过、返回、暂停和重启恢复。未填风险限制保持未知，不代填一个似乎适合所有人的仓位。个人默认值可在 `investment_defaults` 配置；未改变的配置值不会在重启时覆盖聊天修改。个股逐字段继承；显式禁止、数值 0 与未知有不同含义。

AI 复用 AstrBot 当前会话模型，或配置 `model_provider_id`，无需新增厂商密钥。每次 `/分析` 会向选定模型发送该次行情指标、组合暴露、个人偏好和所选材料；模型本身可能产生已有服务的调用费用。模型没有工具和历史聊天权限，不能下单或更改账本。模型不可用或返回无效结构时，报告保留程序观察并说明缺口。`/盯盘 深度 MU` 最多使用五个研究角色加一次汇总，保留分歧；`/盯盘 用量` 查看所有模式共享的每日调用和估算预算。[深度研究与预算](docs/DEEP_RESEARCH.md)。

材料来源：SEC EDGAR 披露与 XBRL 财务数据、允许域名内的公司 IR 页面、Alpaca 新闻接口（Benzinga）。SEC 需在 `sec_user_agent` 或 `STOCKWATCHER_SEC_USER_AGENT` 配置含真实联系邮箱的标识；未配置则跳过并展示原因。IR 默认支持美光页面，其他公司通过 `公司页面` 和 `ir_allowed_hosts` 指定；仅抓取指定页面，不进行整站爬取。没有公开时间的页面只存档，不用于时点研判。新闻权限以实际账户为准，不承诺免费全文覆盖。

缓存模式不会联网，明确标为观察。正常分析也只使用最近已完成且可取得的延迟日线；日历无法核实、资料在收盘后更新或组合估值缺失时，会限制新增风险建议。报告记录行情归属、抓取/公开时间、材料版本、设置版本及上次判断的变化。

目标候选仅支持“已核实历史年度 EPS × 明确假设倍数”的估值情景，程序复算价格，7 天内且设置未变化时可显式采用。没有适用财务数据则不生成该类目标，不把技术上涨当作企业价值证明。回调价区是候选，使用 `/盯盘 计划 采用 报告ID` 后才保存为条件计划，仍需开启监控。风险等级是版本化的描述规则，20% 下跌是人为压力情景，均不是概率或收益保证。[详细规则](docs/RULES.md) · [完整命令与边界](docs/USAGE.md)。

## 监控与日报

```text
/盯盘 提醒目标 当前
/盯盘 推送测试
/盯盘 监控 开启
/盯盘 日报 开启
/盯盘 监控 状态
/盯盘 监控 巡检
/盯盘 监控 关闭
```

默认关闭；开启后每 300 秒巡检，持仓优先，每轮最多 5 只，超额明确列出。默认日报只做程序观察，无模型费用；`日报 AI开启` 才让日报调用模型。默认免扰为展示时区 22:00～07:00，日报时间默认 07:30。作业、通知和分段进度持久化；设置或账本变化会停用旧计划。[监控与通知边界](docs/MONITORING.md)。

## 持仓与成交账本

以下数字为操作示例，不代表真实行情。日期是纽约当地日期，可省略为纽约当天；同日事件按登记顺序计算。若需要回填同日事件的先后顺序，应先撤销受影响的后续记录，再依实际顺序重录。

```text
/盯盘 持仓 添加 MU 数量=10 成本=100 日期=2026-10-16
/盯盘 现金 设置 5000 日期=2026-10-16
/盯盘 关注 添加 MSFT 理由="等待 回调"
/盯盘 成交 买入 MU 数量=1.5 价格=100 费用=0.5 日期=2026-10-16
/盯盘 成交 卖出 MU 数量=1 价格=110 费用=0.5 日期=2026-10-16
/盯盘 持仓
/盯盘 关注
/盯盘 记录
/盯盘 撤销 4 原因=成交价录错
```

- 代码可写 `MU` 或 `US:MU`，暂不接受公司中文名或其他市场代码。
- 使用 Decimal，输入最多 12 位整数、8 位小数，不使用浮点数记账。
- 加权平均账面成本包含买入费用，卖出费用抵减收益；不是税务批次或报税成本。
- 期初持仓不反推现金，也不补造更早的交易收益。同一股票存在有效记录时，不能用“期初持仓”直接覆盖它。
- 现金初始为未知，允许登记实际交易但不会声称校验过购买力。设置余额后，重放过程中现金不能为负。
- 现金是手工登记的记账余额，不是券商已交收资金、融资购买力或可卖数量；本版不模拟交收和融资，不校验实际交易权限。
- `现金 设置` 是当时余额快照，之后的交易与资金事件从该余额计算；更早历史不覆盖之后的余额快照。建议先录入期初持仓和对应时点的现金，再录后续成交。
- 同一平台消息 ID 的重复投递不会重复入账；手工重复发送的新消息是新的登记，有新的记录 ID。
- 撤销保留原记录与原因。如果撤销会造成后续超卖或历史负现金，将拒绝整个撤销操作，需按依赖顺序更正。

其他资金与拆股事件：

```text
/盯盘 现金 入金 1000 日期=2026-10-16
/盯盘 现金 出金 100 日期=2026-10-16
/盯盘 现金 收入 10 日期=2026-10-16 备注=现金分红
/盯盘 拆股 MU 比例=2:1 日期=2026-10-16
/盯盘 关注 移除 MSFT
```

拆股改变数量、保留总成本；碎股处置和现金替代需按券商实际结果核对，不自动推断。现金收入不冒充股票卖出收益。持仓和关注状态独立保留，移除关注不删成交。

## 主动消息测试与生命周期

```text
/盯盘 提醒目标 当前
/盯盘 推送测试
/盯盘 提醒目标 清除
```

提醒目标只保存选定会话。没有保存目标时，测试向当前会话发送；测试通过不代表已开启自动监控，也不保证平台最终送达。某些平台不支持主动消息，需要在实际平台核实。

插件维护一个后台巡检任务，未开启时不查询外部数据。重载/卸载会取消巡检及正在进行的查询/发送，关闭 HTTP 客户端和数据库。重启恢复已开启的订阅；显式关闭则不恢复发送。平台可能在已接收消息后发生进程退出，因此不能保证严格只送达一次。

`/盯盘 备份` 生成本地 SQLite 一致性快照，`备份 列表` 查看文件名，不在聊天中发送个人数据。恢复前停用插件，使用 `python -m stockwatcher.maintenance restore 备份路径 新数据库路径`；拒绝覆盖现有目标，恢复后监控关闭且需重新选择接收会话。详见 [安装/备份/恢复](docs/INSTALL_TEST.md)。
