# 消息入口白名单与专用私聊

插件设置「01 · 入口与聊天」中的 `access.allowed_origins`，界面名称为“消息入口白名单（至少添加一个私聊入口）”。可逐项添加多个入口，支持同一人的多平台账号和多个私聊会话；不是只能填写一个。

## 首次配置

1. 在想授权的私聊向机器人发送 `/盯盘 入口` 或 `/stockwatch 入口`。
2. 复制返回的完整 UMO，例如 `平台实例ID:FriendMessage:会话ID`。
3. 打开 AstrBot 插件设置，将每个 UMO 分别添加到消息入口白名单，至少一项。
4. 保存并重载插件，再使用 `/盯盘 状态` 或直接说“隐藏设置总览”。

空列表允许插件处于待配置状态，以便查询本会话标识；此时不打开业务数据库、不创建行情客户端或自动巡检任务，所有业务指令均被拒绝。空列表永远不表示允许所有人。列表中的空项、错误格式、群聊标识和通配符会报配置错误，不能算作有效入口。

UMO 的第一段是 AstrBot 平台实例 ID，不一定是 `qq_official` 等适配器名称；最后的会话 ID 也不一定是你平时看到的账号号码。应复制实际返回值，保持大小写。不会把首个联系机器人的人自动设为所有者，也不提供通过聊天修改白名单的命令。

## 能访问什么

业务指令在读取账本、修改设置、查询行情、调用 AI 或推送测试之前，先校验可信的消息类型、群组标识和完整 UMO。消息正文中的昵称、发送者声明或伪造的入口文本不能代替事件元数据。

- 仅支持私聊；即使有人手动填写群聊 UMO，也不能放行群聊。
- 所有白名单入口共享同一份个人持仓、设置和报告，并具有相同的读写能力。不要把不应查看个人数据的会话添加进去。
- 没有独立成员、角色、管理员层级或多用户账本隔离。
- `/盯盘 入口` 是唯一的只读配置辅助入口：未获准的私聊也只能看到它自己的 UMO，看不到全局白名单、账户状态、持仓、模型或凭证，不写入个人数据。

## 提醒和权限撤销

`提醒目标 当前` 只能由已经授权的私聊执行。自动巡检、日报和推送测试要求接收目标仍在白名单内，每次插件模型调用前也会复核入口授权；旧版保存的群聊或其他未获准目标不会继续接收消息。

从设置中移除接收入口后，自动任务暂停，发送队列在发送前以及每段长消息之间再次检查；`监控 状态` 中 `notification_target_allowed` 表示当前目标是否仍被允许。可从另一个仍被授权的私聊重新设置提醒目标。已经发到平台或发送中的一段无法撤回。

配置变更请保存并重载；重载会取消旧任务再按新配置建立资源。若宿主原地更新同一个配置对象，后续命令和发送检查也会使用新白名单，格式错误时按全部拒绝处理。

## 从旧版本升级

旧版本没有此字段，升级后默认空列表，不会沿用“任何入口均可调用”的行为。已有持仓和数据库不删除，但在补齐白名单前不会打开业务服务或恢复自动任务。配置自己的私聊入口后，核对持仓与旧提醒目标，必要时重新执行 `提醒目标 当前`。

这是聊天入口的访问控制。本地数据库文件、备份和维护 CLI 仍由部署机器本身的文件权限管理。

## v0.7.0 的配置分组与自然语言

旧的根级白名单和数据配置保留为隐藏迁移字段，宿主不会在插件加载前删除旧凭证。插件只迁移一次到新分组，随后白名单以 `access.allowed_origins` 为准，清空后不会回退到旧授权。原有数据和已保存提醒目标保留。

默认专用私聊接管普通文字，仅限白名单中的可信私聊事件；未授权或群聊消息不会因此初始化数据库或调用模型。复杂表达经模型识别后仍由程序校验并处理；写操作先展示草稿，原入口确认后保存。模型调用前与回复各分段均再次检查授权。

提醒目标也可在「04 · 提醒与日报」填写；选择的入口必须仍在白名单内才会执行后台任务或发送。原有聊天开关会同步回配置页，详见安装指南。
