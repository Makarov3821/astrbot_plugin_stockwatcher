# AI 决策辅助：持有路径、目标复核与回调入场

状态：设计稿，尚未实现。以美股、单人私人助理为首版范围。

## 1. 定位更新

AI 参与判断，不仅解释规则结果：评估持有逻辑是否仍成立、上涨空间是否值得继续承担风险、目标是否需复核，以及回调入场条件是否充分。程序提供可验证数据、计算和监控执行，校验最终建议是否符合已确认的约束。用户作出实际交易决定，成交仍由用户登记。

以下 800、1000 和下跌 20% 均为用户提出的假设，不代表当前美光行情或实际预测。

## 2. 必须分开的对象

| 对象 | 含义与维护方式 |
| --- | --- |
| 个人目标 | 用户期望的价格与实现期限，保留原始理由 |
| AI 目标候选 | 带依据、条件与期限的调整建议，不覆盖个人目标 |
| 过程风险 | 到达目标前可能遭遇的回撤、波动和资金占用 |
| 逻辑失效 | 哪些新事实会否定原来的持有依据 |
| 当前计划 | 基于当前证据和约束形成的观察、持有或操作建议 |

目标有上行空间不能单独推出现在应买入或继续满仓持有。短期风险上升也不能单独证明长期目标失效，需要分开分析。

## 3. 场景一：有持仓，目标尚未达到

输入包含：当前价格、成本、持仓数量和权重、用户目标及期限、买入理由、可接受回撤、近期与历史行情、基准表现和可得事件材料。用户未填回撤偏好时可提示补充，不替用户判断其能承受多大损失。

分析同时回答：

1. 长期目标依据是否仍成立，有哪些新证据或反证。
2. 未来观察窗口的波动与回撤暴露是否升高。
3. 当前仓位在不利情景中可能造成多大账户损失。
4. 继续持有、降低部分暴露、暂不加仓等方案各自的代价及触发条件。

对于“800 跌 20% 至 640，再恢复到 1000”的描述，640 只是压力情景。系统可以根据历史窗口与事件材料讨论这种幅度的风险，不能承诺会先跌再涨，或必然回到目标。样本频率注明样本、条件和窗口，不冒充未来发生概率。

可选支持长期底仓与机动仓的分析视角，用户未启用时不自动拆仓；分批方案仍需考虑费用、执行可行性和错失上涨的风险。首版可以对同一持仓给情景比较，不必先实现独立双仓账本。

## 4. 场景二：目标价可能过于保守或过于乐观

AI 可建议维持、上调、下调或暂无法判断，并说明：

- 目标适用期限及新旧假设。
- 相比上次判断新增了什么证据。
- 支持与反对调整的材料。
- 基准、乐观与不利情景，避免只给上涨路径。
- 数值是用户目标、技术位置、估值结果还是压力情景。

量价走势可以支持技术位置和动量研判，不能独立证明企业价值。基本面目标复核需可追溯的业绩、指引、估值假设等材料；首版允许用户提供或通过受支持的数据接口补充。材料不足时明确保留原目标并暂停估值型修订，仍可给技术观察。

如采用估值计算，模型提出参数与假设，程序执行计算并保存输入；不得只因价格上涨就机械上调目标。候选不应被包装为具有统计覆盖率的置信区间。

用户采用目标调整后保存新版本，重新评估相关条件；拒绝或暂不处理不改变个人目标。AI 本轮判断仍可在报告中保留。

## 5. 场景三：看好上行空间，等待回调入场

首先核实“上行空间”来自个人预期还是有证据的估值假设。近一两周连续上涨可作为观察条件，不等于必然即将回调。计划必须包含没有回调继续上涨的路径，用户可以选择接受错过，或另行启用受支持的突破入场策略。

```text
等待机会
  → 进入候选区域
  → 等待预先定义的企稳或确认条件
  → 条件满足：生成入场建议并提醒
  → 实际买入登记后转为持仓管理

任一阶段 → 逻辑失效 / 跌破风险条件 / 超过等待期限 → 暂停并重评
```

AI 可综合趋势、回调幅度、量能与事件材料提出候选区域及确认条件；触发器必须能映射为实际可获得的数据。没有分钟线时，不声称确认了盘中结构；日线规则等完整收盘数据才能确认。

重点区分健康回撤与趋势破坏，进入低价区不自动等于买点。报告给出允许考虑的区域、确认条件、入场后失效条件、仓位上限及有效期，而非声称捕捉最低点。任何提醒都不自动记为成交。

## 6. 风险系数的设计

首版优先显示低/中/高分项及解释，具体评分阈值在实现前定义并版本化。可选总分只能表示明确评分规则下的风险强度，不表示未来亏损概率。

| 分项 | 观察对象 |
| --- | --- |
| 短期回撤风险 | 指定的未来观察窗口；依据近期波动、偏离与历史情景 |
| 持有逻辑风险 | 关键假设与反证，包含尚缺的基本面材料 |
| 事件风险 | 财报等事件的时间与已知信息，日期未知明确标记 |
| 仓位风险 | 用户持仓集中度与压力情景中的账户影响 |
| 证据充分程度 | 来源覆盖、新鲜度、缺失；单独列出，不与风险分数简单相加 |

窗口分开，例如“未来 5 个交易日的波动暴露”与“未来数月的目标情景”。历史波动、ATR 或模型自评分不能直接当作预测区间、预期最大损失或经过校准的概率。若未来增加概率模型，必须专门验证覆盖率、样本外校准与适用范围。

## 7. 分析与监控执行

1. 收盘后或重要新材料到达时构建证据包：行情时点、特征、持仓、用户预期、历史判断和来源。
2. 程序生成基线观察及约束；AI 生成结构化研判，可以与基线不同，但须列出依据和反证。
3. 校验引用是否存在、数值是否可复算、条件是否可执行、有无过期材料和约束冲突。
4. 保存本次判断，不因重试覆盖先前记录。输出与上次相比变化及原因。
5. 按用户已选择的监控偏好启用支持的观察条件；目标或风险限制的调整先由用户采用，未采用不改变个人设置。
6. 盘中主要运行已有条件检查，触发或出现重要新信息时才重新研判，避免每次报价都改口。

历史判断是上下文，不是事实依据；不能用“上次看多”代替新证据。AI 不可用时继续执行有效的规则监控，明确暂停需要模型的新研判。

## 8. 报告字段与验收

报告分别展示：用户目标与期限、AI 当前判断、可验证观察、分项风险、证据缺口、情景比较、当前建议、下一触发条件、失效条件、与上次的变化。尚未计算的项目显示未知，不填示意性风险数字。

重点验收：

- 对用户假设的 800/1000 不引用为真实行情。
- 没有业绩或估值材料时，不编造所谓合理目标价。
- 短期风险上升与长期观点可以同时存在，并明确差异。
- 下跌 20% 的压力情景不被写成必然路径或最大亏损保证。
- 上调目标的建议不自动覆盖用户设置。
- 关注池进入区域但未企稳时不直接输出已确认买点。
- 不回调继续上涨时，有明确的等待或重新评估行为。
- AI 与规则分歧时报告分歧，最终结果符合已确认约束。
- 保存输入、模型和提示模板版本，使用前向模拟评价 AI 决策增益。
