# v0.3 监控、日报和条件计划

首次安装默认全部关闭。先选接收会话，再明确启用：

```text
/盯盘 提醒目标 当前
/盯盘 推送测试
/盯盘 监控 开启
/盯盘 日报 开启
/盯盘 监控 状态
/盯盘 监控 巡检
```

持仓优先，其次活跃计划和关注池，每轮最多 `monitor_max_symbols`（默认 5）。超出部分不会悄悄宣称已监控，会列在状态/覆盖提醒中。巡检默认每 300 秒，常规时段查询有延迟的完整分钟线；收盘日线就绪后运行每日程序检查。Alpaca 日历处理节假日、夏令时和提前收盘，异常旧数据不触发新条件。

持仓巡检检查个人退出价、目标与成本回撤。持仓高点等依赖日线的规则在收盘程序检查计算。分钟提醒以最后已完成分钟的收盘价检查持仓阈值，盘中瞬时穿越但未落在采样收盘上的事件可能漏报。规则提醒不会登记卖出或声称已经成交。

日报按个人 `日报=HH:MM`、展示时区发送最近完整交易日的报告；同一设置版本去重，修改设置后可以重新生成。正常停机后恢复只补最近交易日，不追发整个停机期间。默认程序日报，不调用模型；`/盯盘 日报 AI开启` 才启用 AI 研判。`/盯盘 日报 关闭` 关闭日报；`/盯盘 监控 关闭` 停止所有自动检查和取消待发送通知。

默认免扰为展示时区 22:00～07:00，可改为：

```text
/盯盘 监控 设置 免扰开始=22:00 免扰结束=07:00 自动采用=否
```

开始和结束相同表示不设免扰。所有通知遵守免扰，明确退出提醒也不会绕过；过期的入场提示不因等到可发送时段而继续发送。

`/盯盘 分析 MU` 生成回调候选后，用 `/盯盘 计划 采用 报告ID` 保存计划。只有有效行情、未过期且校验通过的报告可以采用，个人设置和账本还需与报告一致。`自动采用=是` 仅作用于之后手动生成的新报告，不自动更改目标或风险参数。

计划状态：`waiting → armed → triggered`；失效价、有效期、取消、设置变更和账本变更可结束计划。进入候选区仍需完整日线确认，并重新检查当前风险预算。未回调会继续等待至过期；已进入但离开候选区不会冒称当前可以买。采用当日的日线高低价可能早于采用时刻，因此只用该日收盘确认位置，或使用采用之后的分钟记录，避免将采用前事件当成后续触发。

`/盯盘 计划` 查看；`/盯盘 计划 取消 ID` 取消。登记实际买入后按持仓继续监控。计划只编译支持的价格区间和两种日线确认，不自动执行 AI 自由文本中的所有失效条件，重大新闻仍需人工复核。

作业和待发送通知保存 SQLite，正常重启恢复。每日作业唯一键防重复，失败最多尝试 3 次；通知退避重试最多 5 次，可 `/盯盘 通知` 查看并 `/盯盘 通知 重试 ID` 重试未过期的最终失败项。长消息按段保存进度，不重发已确认的前段。进程恰在平台接收后、落库前退出仍可能重复，通知 ID 可辨识，不声称严格只送达一次。

偏好或账本变化会停用旧计划，发送前还会再次核对报告和触发提醒的版本。已在平台发送中的一段无法撤回。配置或数据失败保留缺口，普通巡检不调用模型也不影响手工账本。
