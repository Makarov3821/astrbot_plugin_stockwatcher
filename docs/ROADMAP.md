# StockWatcher 分步实施计划表

状态：第 01～10 步代码与安装测试包已完成；真实 AstrBot/平台、数据账户与模型验收待目标环境。第 11 步尚未开始；真实部署验收由安装试用继续完成。第 07 步“真实数据首份报告”验收仍未完成，不以离线样例代替。详细证据和边界见 [验证记录](./VALIDATION.md)。

本文作为实施顺序与进度的主表；PLAN 描述架构，其他设计文档提供具体约束。实现时在对应步骤讨论个人偏好，工程实现细节直接推进，不要求提前完成所有选择。

## 1. 首版范围

美股普通股票、单人私人助理、免费行情优先且接受延迟、持仓与关注池、手工成交账本、AI 决策辅助、按需多智能体研究、收盘分析与低频盘中提醒。首版不自动下单；港股和 A 股在美股流程验收后扩展。

## 3. 用户何时参与选择

| 对应步骤 | 届时讨论的内容 | 不阻碍的工作 |
| --- | --- | --- |
| 01 | 目标 AstrBot 版本、实际使用平台与提醒接收位置 | 插件目录、模块边界、配置结构 |
| 02 | 实际可用的数据账户；需要凭证时通过配置页或本地安全位置填写 | 数据接口、缓存、离线样本验证；没有实际权限时不能宣称接入验收通过 |
| 03 | 先录入哪些持仓、期初数据与成本口径 | 通用账本、迁移、更正机制 |
| 04 | 持有周期、目标、回撤基准、加仓偏好、硬限制与默认模板选择 | 引导流程、字段继承、草稿存储 |
| 05 | 如关键材料缺失，是否手工补充或接受该项能力暂缺 | 可用公开披露接入、去重、引用记录 |
| 07 | 使用哪个已有模型、报告详略、是否主动复核目标 | 结构化输出与验证；缺少模型配置时先完成离线和错误路径，真实研判随后验证 |
| 08 | 日报时间、免打扰、是否自动监控 AI 提出的受支持条件 | 调度、去重、状态恢复 |
| 09 | 深度研究触发方式与调用预算 | 分工流程、证据约束和失败处理 |

不在聊天中索取明文凭证，不要求额外的注册/角色/成员管理。明确的设置指令直接反馈保存结果；有歧义时再澄清。目标、风险限制和实际成交不因 AI 提案自动改变。

## 4. 每阶段能用到什么

- **步骤 01～02：接入验证版。** 确认宿主、免费行情与部署网络能实际工作，决定主数据源，尚不宣称能够个性化决策。
- **步骤 03～04：个人记录版。** 能维护持仓与关注股票、记录交易与偏好，重启后继续使用。
- **步骤 05～07：分析版。** 能主动请求单股分析，获得目标复核、持有路径及回调入场的证据化报告；开始保存前向评估记录。
- **步骤 08：可日常试用版。** 能按时复盘、监控有效计划、接收变化提醒。
- **步骤 09～10：完整首版。** 加入按需深度研究，通过运行与数据恢复验收后交付。
- **步骤 11：效果观察。** 在实际使用中持续记录，依据结果修订规则和提示，不以交付完成声称收益已经验证。

## 5. 三条核心验收故事

1. **已有持仓。** 用户设定目标与期限，系统发现短期风险升高，分别说明长期逻辑、回撤与仓位影响，形成有期限的建议；用户更正交易后重新计算。
2. **目标复核。** AI 引用新材料提出上调或下调候选，个人目标保持；采用后生成新版本并更新监控，未采用继续保留旧设置。
3. **等待入场。** 进入候选区、等待确认、满足条件、条件失效和始终不回调都能正确转换；实际成交登记后转入持仓流程。

场景中可使用用户提供的美光假设价格作为离线样例，但实时验收必须采用获取到的实际数据并显示时点，不把示例价格写成真实行情。

## 6. 验证方式和阶段收敛

- 离线测试覆盖账本、继承、计算、约束、状态变化和去重；不依赖模型用词与每天变化的网络数据。
- 实际环境验证宿主加载、消息发送、数据访问权限、时间口径和模型输出结构；记录未能验证的接口与原因。
- 重复同一输入应产生相同程序指标与约束结果；AI 保留原始输出与版本，不要求重复调用逐字一致。
- 接口不可用时完成独立工作，保留故障记录，不以示例数据替代真实接入验收。
- 每步只做本步必要功能与相应检查；根据真实失败和证据修订后续计划，不反复扩展前置讨论。
