# 设置、聊天和研判操作

首次使用先按 [安装和设置指南](INSTALL_TEST.md) 配置长期偏好与入口。默认专用私聊支持自然语言，见 [聊天说明](CONVERSATION.md)；可直接说“隐藏设置总览”或“我现在的大盘走向判断是什么”。本页保留原有明确指令作为精确操作入口，不必先完成旧引导。

## 分步设置

首次普通查询只显示一次引导入口。个人引导依次补充账户、策略/周期、风险、回撤、大盘预期和通知偏好；安装时已明确填写的项目跳过。`/盯盘 开始 MU` 仅补充这只股票缺少的目标/期限、理由、加仓偏好，其他字段继承个人设置。

本节的旧引导仍用固定短回答与 `键=值`，带空格的值使用引号。v0.7.0 另有自然语言意图识别和中文草稿确认，查询直接读记录。明确指令仍直接按给定参数执行，不含隐式成交或自动订阅。

在发起或恢复引导的白名单私聊中，可以直接回复 `跳过`、`采用默认`、`暂不判断`、`暂停`、`返回`、`取消`，或按本步格式填写，例如 `允许加仓=否 单股上限=20 总仓位上限=60 单次风险=1`。账户步骤也接受 `现金`、`保证金`、`未知`；待确认时直接回复 `确认` 才保存设置。格式错误会提示未保存，不交给普通聊天模型代答。

暂停、结束后短回答不再作为引导回答处理；独占聊天开启时继续交给自然语言助理，关闭独占时才放行普通聊天。其他已注册指令始终放行。恢复用 `/盯盘 引导 继续`。其他白名单入口共享同一份草稿，但要显式继续后才接收其短回答；旧版未绑定入口的草稿也先用此指令恢复。平台提供消息 ID 时，同一引导消息重复到达不会重复推进步骤，回执保留最近 32 条并随草稿持久化。

| 命令 | 含义 |
| --- | --- |
| `/盯盘 开始 [MU]` | 开始个人或个股引导，已有草稿时恢复；切换股票前先完成或取消 |
| `/盯盘 回答 ...` | 按当前提示回答，也可 `跳过`；策略/通知步骤可 `采用默认` |
| `/盯盘 引导 状态/暂停/继续/返回/取消/确认` | 管理持久化草稿；未确认不生效；超 24 小时的回答先暂停 |
| `/盯盘 设置` | 查看个人默认值和版本 |
| `/盯盘 设置 MU` | 查看个股生效值及每个字段的来源 |
| `/盯盘 设置 [MU] 字段=值 ...` | 直接修改并保存新版本；个股 `字段=继承` 删除覆盖 |

可配置字段：

| 字段 | 取值/含义 |
| --- | --- |
| 账户 | 现金/保证金/未知；不代表已验证交易权限 |
| 策略、周期 | 趋势；1～3650 天，默认 60；本版仅实现一个日线模板 |
| 允许加仓 | 是/否/未设置，未知不会被自动当成允许 |
| 单股上限、总仓位上限、单次风险 | 0～100 的百分数，不带 `%`；风险是入场到失效价的预算，不是亏损概率 |
| 回撤、基准、用途 | 阈值百分数；成本/持仓高点/近20日高点；复核/退出，三者应配套明确 |
| 目标、目标期限、到价 | 正价格、YYYY-MM-DD；提醒/复核/减仓/退出，默认复核 |
| 退出价 | 用户明确的正价格退出阈值，必须低于已设置目标 |
| 理由、复核目标 | 原有持有或关注逻辑；是否允许 AI 提出目标候选 |
| 日报 | HH:MM，按展示时区；另外开启监控和日报后才自动推送 |
| 公司页面 | 单个 HTTPS 公司 IR 页面，域名还需在配置的允许列表内 |

账户、总仓位上限和日报是个人字段，不提供个股覆盖。个股风险上限只能更严格，不能绕过已明确的个人限制；设为未设置也不能消除个人上限。缺少组合现金或任何持仓的同日估值时，不计算精确权重或新增资金上界。

`/盯盘 大盘预期 偏多/中性/偏空/暂不判断 期限=YYYY-MM-DD [基准=SPY 理由=...]` 以纽约日终为期限，过期停止应用，历史保留。本版仅作背景，不因看多放宽风险上限；尚不提供自动到期提醒。

## 证据与分析

`/盯盘 材料 更新 MU` 刷新 SEC、新闻和配置的 IR 页；`材料 列表 MU` 查看时点可用的来源。未设置 SEC 联系标识、新闻权限不足、接口异常都会展示缺口，不能解释为无新闻。

手工材料示例：

```text
/盯盘 材料 添加 MU 链接=https://example.com/release 标题=用户摘要 发布时间=2026-10-16T20:00:00Z 内容="自己整理的观察"
```

手工材料始终标为未经抓取核验的用户备注，不能冒充已核实 EPS。来源核验仅指数据来自指定接口或域名，不代表新闻中的传闻或观点已被证实。同一规范链接保留更正版本；删除追踪参数而保留有意义的查询参数。相同标题和正文的新闻转载只纳入一份，近似改写尚不做语义去重。撤回版本不会回退为旧的有效材料。只有公开且已经首次观察到的内容可进入相应时点报告。

`/盯盘 分析 MU` 获取原始和 all 调整日线、SPY 或指定基准、日历与材料，再调用一次 AstrBot 模型。自然语言分析还会把原始问题传给研判，避免只识别股票代码而丢失“今年走势、回调是否见底”等关注点。`分析 MU 缓存` 不联网，不能作为当前执行建议。没有原始及调整快照则明确失败，绝不注入演示数据。

程序计算指标、风险预算和压力情景；模型解释持有逻辑、反证和回调候选。模型引用必须来自输入；目标价格由程序计算；候选入场价格关系、期限、仓位约束均经过检查。`validated` 表示通过上述结构和特定数值约束，**不证明引用与全部文字在语义上匹配，也不证明预测正确或收益可靠**。

模型输入材料正文每篇最多 1600 字，最多 15 篇，仍受总输入字符预算限制，提示中记录截断和省略数量；并非每篇全文阅读。数据库保存所抓取内容及本次证据包、实际提供的材料覆盖、行情快照、设置版本、提示版本、模型标识、可得用量和原始输出，不保存模型隐藏推理。报告对比上次参考价、材料版本和设置版本。

`分析记录 MU` 列最近 10 次，`报告 ID` 查看已有报告简报，`报告 ID 详情` 查看完整依据与诊断；也可自然语言说“查看详细依据”读取本入口上次报告。打开报告不联网、不调用AI，过期报告会注明。相同平台消息重复投递只返回原报告；另发消息是一次新研判。生成期间设置或账本变化时保存为 `superseded`，不产生活跃目标候选；模型失败保存为 `degraded`，用户明确的退出条件仍可由有效行情触发程序观察。

`目标` 查看最近候选，`目标 采用 ID` 才更新个人目标和期限，`目标 拒绝 ID` 保留原目标。候选 7 天后、设置版本变化后不能直接采用。历史 EPS 仅支持情景，估值倍数由模型提出，尚无前瞻盈利预测和拆股后 EPS 专项核对；应结合原始财报审阅。

v0.5 已提供显式采用的条件计划、持续监控和日报，见 [监控说明](MONITORING.md)；按需多角色见 [深度研究](DEEP_RESEARCH.md)，首次安装及备份恢复见 [安装试用](INSTALL_TEST.md)。自然语言修改范围见 [聊天说明](CONVERSATION.md)，不支持订单执行。历史回撤、ATR、风险等级和压力情景不代表未来损失概率。

## 简报与详情

默认简报优先展示结论、行情交易日、价格、年内涨跌幅（有跨年基准时）、均线、近期回撤、波动和主要信息缺口。金额和百分数显示两位小数，保留底层计算精度。缺少个人风控参数只影响数量或新增风险判断，不再逐字段刷出英文缺失项；未持仓不展示零损失压力情景。

AI引用错误或其他校验失败时，明确标记“AI未完成”，不把程序观察冒充有效AI判断。引用规则保持严格：支持/反证需要合法引用，未知事件或持有逻辑可按规则保留未知；详情记录发生问题的字段。底部不能由反弹或一条均线信号保证，简报与模型提示都会保留这一不确定性。

完整报告仍保留所有材料、排除原因、内部风控状态、原始精度、角色观点及候选采用状态，只有主动打开详情才展示。最近报告指针按入口保存，不会把另一入口的上次请求当成本次上下文。

## v0.7.2 深度报告

深度研究使用专门的角色摘要，开头展示是否完整完成，并列出成功角色各自的期限、观点、论点与疑点，缺失角色及失败类别直接显示；普通分析仍展示简洁行情依据。汇总通过格式和引用校验不等于五角色全部成功。全部角色失败时不再额外启动单模型汇总，直接说明深度未完成。更新后可重看原报告获取已保存的角色信息，不增加调用；详情显示完整论据和错误。

## v0.7.3 引用校验与诊断

引用可指向本次实际提供的 `metrics`、`portfolio`、`preference`、`source_gaps`，也可使用这些对象中确实存在的点分隔字段路径，例如 `metrics.ma20` 或 `preference.values.allow_add`。每一级都必须真实存在；未知字段、其他命名空间、未提供的新闻编号以及已经裁掉的材料仍拒绝，不会模糊补全错写的新闻ID。事件风险判断仍要求实际材料引用，不能只用“存在材料缺口”证明某个事件已经发生。

模型上下文移除上一份报告的材料版本编号表，避免把历史编号误当本次输入；用于审计与报告比较的原始历史保持不变。深度记录另外保存角色实际获得的裁剪后材料清单、允许引用范围、已返回原文、模型元数据及具体失败字段/引用，不只是成功角色。没有额外模型重试或调用。

使用 `/盯盘 报告 ID 引用诊断`，或说“看看引用诊断”“报告3引用诊断”，读取短诊断视图。只显示状态、出错字段、被拒绝引用和摘要，不自动发送模型原文或新闻清单。原文保存在本地SQLite报告的model_json中；这不是模型隐藏推理。

v0.7.2及更早的失败角色原文没有保存，旧报告只能保留失败摘要，无法事后还原错误ID；不能根据复制文本里的下划线或格式变化猜测原始引用。新诊断不会补造旧数据。
