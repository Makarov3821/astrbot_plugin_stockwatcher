# v0.5.0 首次安装与试用

这是首个可安装测试版。离线测试已覆盖关键链路，真实平台、模型输出和免费数据权限留待你的环境验收；功能完成不代表策略收益已验证。先用一只关注股和少量真实记录试用。

## 安装

1. 使用 Python 3.12+ 的 AstrBot。推荐先用接口核对过的 `4.29.1` 或兼容更新版本；声明的范围不代表所有版本均已实测。
2. 从开发机 `dist/` 取 `astrbot_plugin_stockwatcher-v0.5.0.zip` 和同名 `.sha256`。可用 `sha256sum -c astrbot_plugin_stockwatcher-v0.5.0.zip.sha256` 核对。
3. 在 AstrBot 插件管理的本地 ZIP 安装入口上传。也可将 ZIP 中的 `astrbot_plugin_stockwatcher` 文件夹放入宿主 `data/plugins/`，确保 `main.py` 直接位于该文件夹下，不要套两层目录。
4. 安装 `requirements.txt` 依赖并重载插件。宿主无法自动安装时，在其实际 Python 环境执行 `python -m pip install -r data/plugins/astrbot_plugin_stockwatcher/requirements.txt`。Docker 用户在容器使用的环境安装，勿只装在宿主机另一个 Python 中。
5. 发 `/盯盘 帮助`、`/盯盘 状态`。出现 `StockWatcher 0.5.0` 与数据库版本 `4` 即完成入口和存储的第一项检查。

ZIP 不包含 AstrBot 源码、开发环境或数据库，运行不依赖开发机的 `astrbot-temp` 软链接。包内 `RELEASE_MANIFEST.json` 记录源提交、源码是否有未提交变动及逐文件哈希。重新打包可在仓库根目录执行 `python scripts/build_release.py`。

## 配置

| 项目 | 如何填写 |
| --- | --- |
| Alpaca | 配置页 `alpaca_key_id`、`alpaca_secret_key`，或进程环境 `APCA_API_KEY_ID`、`APCA_API_SECRET_KEY`；`paper/live` 与凭证一致 |
| SEC | `sec_user_agent` 填插件标识及自己的真实联系邮箱；不填则跳过 SEC，报告显示缺口 |
| AI | 先在 AstrBot 配好模型；插件 `model_provider_id` 留空沿用当前会话，无需新建厂商密钥 |
| 预算 | 默认每天 24 次调用及 200000 估算 token 预留；深度单轮最多 6 次。预算不是精确账单上限 |
| 时区 | 默认 `Asia/Shanghai`；美股交易时间按纽约日历处理 |
| 监控 | 默认关闭。接收会话、监控、日报均从聊天显式选择；默认程序日报，不调用 AI |

`configs/minimal.json` 是无凭证示例，可对照配置页填写；不用把示例另放成运行配置文件。凭证不要发到聊天。未知的资产、风险限制保持未知；安装模板不会代你决定风险承受能力。

## 第一轮手工测试

按顺序进行；遇到缺口先看提示，不要把 `not_verified` 或 `degraded` 当作成功。

| 操作 | 应观察到的结果 |
| --- | --- |
| `/盯盘 开始` | 逐步补齐未设置的偏好；可跳过、暂停、继续，确认前不改变生效设置 |
| `/盯盘 关注 添加 MU 理由=观察回调` | 加入关注池，不产生持仓或成交 |
| `/盯盘 诊断 MU` | 真实账户日历、日线/调整日线及允许的分钟数据；无凭证或无权限应明确失败 |
| `/盯盘 材料 更新 MU` | 各来源结果与缺口；抽查原文链接、日期和报告期，尤其确认 SEC 能否访问 |
| `/盯盘 分析 MU` | 显示行情交易日、个人期待、证据和反证、分项风险；缺风险/现金时不生成缺依据的买入数量 |
| `/盯盘 深度 MU` | 五角色和汇总、各自期限、分歧及失败角色；随后 `/盯盘 用量` 查看调用 |
| `/盯盘 分析 MU 缓存` | 明确缓存模式，仅供观察；不悄悄把旧数据当成当前价格 |

已有仓位再按自己的真实账单录入期初数量、成本和对应现金。不要把 README 的示例数字当真实数据。先核对 `/盯盘 持仓`、`现金` 和 `记录`；更正使用撤销，不能直接覆盖已有持仓。

用 `/盯盘 开始 MU` 仅补这只股票的目标/期限、理由和加仓偏好。目标价只是个人期待。若报告有 AI 目标候选，应确认原目标仍在；`目标 采用 候选ID` 才修改目标，`目标 拒绝 候选ID` 保留原目标。采用目标或改风险参数后，旧计划应停用，需重新分析。

## 第二轮持续运行测试

```text
/盯盘 提醒目标 当前
/盯盘 推送测试
/盯盘 监控 开启
/盯盘 日报 开启
/盯盘 监控 状态
/盯盘 监控 巡检
```

先人工确认收到推送测试。有些平台不支持主动消息，接口返回成功也不证明平台已最终送达。免扰时间内会排队；测试时可临时 `监控 设置 免扰开始=00:00 免扰结束=00:00`，测试后恢复偏好。

若报告有可用回调候选，用 `计划 采用 报告ID` 保存，再用 `计划` 查看等待/确认/触发/失效状态。不要为了测试提醒而修改真实持仓或虚构成交；价格不进入候选区时继续等待、到期终止是正确结果。监控不会自动买卖。

每轮默认最多 5 只，超额会列出；首次分析其他持仓可能缺同日估值，可先分别查询行情再复核组合风险。普通巡检和程序日报应不增加模型调用。只有明确 `日报 AI开启` 后日报才用 AI，且共享预算。

重载插件后检查持仓、偏好、计划、预算和订阅保留。发送 `监控 关闭` 后应停止自动检查与后续发送；重启后仍关闭。`通知` 可查失败项，`通知 重试 ID` 重试未过期失败消息；`监控 重试` 可重置失败作业，下轮仅执行当前交易日适用任务。

## 备份、升级和恢复

`/盯盘 备份` 用 SQLite 备份 API 在线生成一致性快照，文件位于宿主插件数据目录的 `backups/`，权限设为当前用户读写；`备份 列表` 显示最近文件名。快照含持仓、偏好和报告等个人信息，不含宿主配置里的行情密钥；宿主配置由你另行备份。备份与历史不会自动清除，需按磁盘空间自行归档。

升级前生成一份备份并复制到插件目录以外的可靠位置。数据目录通常为 `data/plugin_data/astrbot_plugin_stockwatcher/`。不要只在运行中复制单个主数据库文件而漏掉 WAL。

恢复必须先停用插件，保留整个原数据目录（包括 WAL/SHM），不要覆盖唯一原件。在插件目录、使用宿主 Python 执行，例如：

```bash
python -m stockwatcher.maintenance inspect /safe/backup.sqlite3
python -m stockwatcher.maintenance restore /safe/backup.sqlite3 /new/place/stockwatcher.sqlite3
```

目标必须不存在；不接受直接覆盖。检查新数据库计数和完整性，确认后再放回已保留原件的宿主数据目录，重载插件。恢复自动关闭监控和日报、清除接收会话、取消旧待发消息，使旧候选停用；持仓、历史和偏好保留。重新核对账本、查询行情、分析和选择接收会话后再开启。

旧版 v1/v2/v3 数据库会自动迁移到 v4。高于当前插件版本的数据库会拒绝打开；回滚旧插件应使用对应旧备份，不能让旧代码直接写新版数据库。恢复的是备份时点记录，并不代表券商最新持仓或提供商当天完整账单。
