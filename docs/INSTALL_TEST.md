# v0.7.5 安装和设置指南

本指南按实际使用顺序说明。先装插件、授权自己的私聊、配置数据，再填写长期偏好，最后按需要开启提醒。大盘判断、关注股票、个股目标无需填写在配置页，通过聊天记录即可。

## 1. 安装并授权自己的私聊

1. 使用 Python 3.12+ 的 AstrBot，在插件管理中通过仓库地址 `https://github.com/Makarov3821/astrbot_plugin_stockwatcher` 安装。建议先用 4.29.1 或兼容更新版；声明范围是 `>=4.28.2,<5`，未逐版本实测。
2. 私聊机器人，发送 `/盯盘 入口`。复制返回的完整会话标识，例如 `平台实例ID:FriendMessage:会话ID`，不只复制最后的号码。
3. 在插件设置的「01 · 入口与聊天」添加该标识，保存并重载。然后发送 `/盯盘 状态`，应看到 `StockWatcher 0.7.5`。

| 设置项 | 做什么、怎么填 |
| --- | --- |
| 消息入口白名单 | 必填至少一个完整私聊标识，可以添加多个。所有获准入口共享你的个人记录。群聊和未授权私聊不能查询或修改；空列表时业务和自动任务停用，只能查自己的入口标识 |
| 由盯盘助理接管授权私聊 | 默认开启。这个授权私聊中的普通文字交给本插件理解，处理后不再交给宿主普通聊天模型。其他插件已注册的命令仍放行；关闭后只保留 `/盯盘` 指令及进行中的引导短回答 |

这里授权的是一个具体私聊，不是某平台上的所有人。即使机器人只供你使用，也需要先完成这一步。

## 2. 配置行情与公告来源

打开「02 · 行情与公告来源」。

| 设置项 | 做什么、怎么填 |
| --- | --- |
| Alpaca API Key ID | 填入你在 Alpaca 账户中生成的 API Key ID。留空也可使用宿主进程环境变量 `APCA_API_KEY_ID`。无凭证仍能记账，无法查询真实行情 |
| Alpaca Secret Key | 与上面同一对凭证的 Secret。也可用环境变量 `APCA_API_SECRET_KEY`。只填配置页或宿主环境，不要通过聊天发送；界面遮罩不等于配置文件加密 |
| Alpaca 凭证所属账户 | 选“模拟账户凭证”或“实盘账户凭证”，必须与密钥来源一致。paper 也是真实市场行情；插件只读资料、日历和行情，不访问订单执行接口 |
| SEC 请求标识与联系邮箱 | 用于抓取公司公告和财务披露。例如 `StockWatcher 你的真实邮箱`。留空则跳过 SEC 并展示材料缺口，不影响账本 |
| 允许抓取的公司 IR 域名 | 允许访问的公司投资者关系网站，默认 `investors.micron.com`。填写域名，不填整条URL。其他公司的实际页面通过聊天或个股设置指定，域名必须同时获准 |

这里的 Alpaca 账户用于取得数据。下面“长期投资偏好”中的账户类型才是你实际使用的投资账户类型，两者互相独立。

保存并重载后，在授权私聊发 `/盯盘 诊断 MU`。应看到日历与非空行情结果；`not_verified`、缺凭证、无权限或数据不足都不能算成功。paper 与 live 使用不同凭证，选错时先核对这一项。

## 3. 填写长期投资偏好

打开「03 · 长期投资偏好」。这些是跨股票沿用的习惯和约束；单只股票的目标、理由等另在聊天里填写。

百分数直接写数字：`20` 表示20%，不要写 `%`。留空表示还没决定，**0是实际限制，不是“未知”**。下面数字均为格式说明，不是建议仓位。

| 设置项 | 做什么、怎么填 |
| --- | --- |
| 账户类型 | 选择尚未指定、现金账户或保证金账户。用于描述你的投资环境，不连接券商，不因选择保证金账户就计算或允许杠杆 |
| 默认策略 | 当前只有“日线趋势观察”。用均线、波动和回撤等描述走势，不代表保证收益，也没有自动运行自定义策略代码 |
| 默认观察周期（天） | 分析时参考的投资时间尺度，默认60天；支持1～3650天。不是必须持满或到期自动卖出的时间 |
| 已有持仓是否允许加仓 | 尚未决定、允许或禁止。允许只是个人意愿，还需满足仓位及风险限制；未知不会被当成允许 |
| 单股仓位上限 | 单只股票市值最多占账户总资产多少。例如20表示20%。计算实际比例还需要完整现金和其他持仓的估值 |
| 总仓位上限 | 全部股票市值最多占账户总资产多少。例如60表示60%；其余可理解为计划保留的现金比例，不自动调整资金 |
| 单次风险预算 | 单次新增仓位从计划入场价跌到失效价时，计划损失最多占总资产多少。例如1表示1%。它不是投入1%的资金，也不是未来亏损概率 |
| 回撤阈值 | 相对下面的基准回落多少百分比时提示处理。留空不设置此规则；填写时必须同时明确基准 |
| 回撤参考基准 | 买入成本：相对成本的亏损；本轮持仓期间高点：相对这轮持有过程最高价的回落；近20个交易日高点：相对近期高点回落。未选择时不据此判定触发 |
| 触及回撤阈值后的处理 | “提醒重新评估”表示检查持有逻辑；“按退出条件提示”表示作为明确退出偏好。两者都不会自动卖出，没有阈值和基准时该偏好本身不构成规则 |
| 日报时间偏好 | 按展示时区解释，默认07:30。需要下一组同时设置接收入口、开启监控和开启日报才会推送；设置这个时间本身不订阅 |

缺少单股上限、总仓位上限、单次风险或完整账户估值时，仍可看行情、趋势、证据与风险观察，但不能计算有完整依据的加仓资金/股数上界。

不必为了开始使用而强行完成旧的聊天引导。可以先保存长期偏好，再直接说“隐藏设置总览”。若仍有旧草稿，可 `/盯盘 引导 继续` 恢复，也可 `/盯盘 引导 取消` 放弃草稿；不会删除已生效设置或持仓。

## 4. 选择提醒入口并开启监控或日报

打开「04 · 提醒与日报」。这组开关就是实际订阅设置，保存并重载后生效，不需要再执行一套聊天开关。

| 设置项 | 做什么、怎么填 |
| --- | --- |
| 提醒接收入口 | 复制白名单中的一个完整私聊标识。可以和安装时的私聊相同。留空不发送主动提醒；白名单中有多个入口也只向选中的一个发送。也可说“把提醒发到这里”，确认后保存 |
| 开启监控 | 默认关闭。开启后按巡检间隔检查持仓及已采用的回调计划。需要有效的接收入口；没有目标或目标已撤销授权时不会开启/发送。普通巡检不调用AI |
| 开启收盘日报 | 默认关闭。监控开启后，按上面的日报时间发送最近已收盘交易日的日报；每天不会因重复巡检重复发送同一份。仅开日报而不开监控不会推送 |
| 日报使用AI | 默认关闭，使用程序日报。开启后调用AstrBot模型生成日报，共享模型预算。此开关不替代“开启监控”和“开启收盘日报” |
| 免打扰开始 | 默认22:00，按展示时区。进入免打扰后通知排队，不会立即发出 |
| 免打扰结束 | 默认07:00。22:00～07:00支持跨午夜；开始和结束相同表示不设免打扰。过期通知不会因为结束免扰就补发 |
| 自动保存新回调候选为提醒计划 | 默认关闭。开启后，只对后续新产生、校验通过的受支持回调候选保存提醒计划，不自动买入；关闭时用明确指令采用候选 |

开启后先发 `/盯盘 推送测试`，人工确认收到消息。平台接口返回成功不保证最终送达；部分平台不支持主动消息。可以直接说“监控状态”检查实际接收入口和各个开关。

## 5. AI理解与研判

打开「05 · AI 理解与研判」。先在 AstrBot 本身配置好模型；插件复用该模型，无需再创建厂商密钥。

| 设置项 | 做什么、怎么填 |
| --- | --- |
| AstrBot模型提供商ID | 可在宿主选择器选择。留空使用当前聊天配置的模型。自然语言识别和研判使用同一个选择 |
| AI单次研判超时 | 默认90秒，每次模型请求的等待上限，包括复杂自然语言的识别。支持5～300秒 |
| 每日模型调用次数上限 | 默认24次，0禁用模型。复杂意图识别、普通分析、多角色研究及AI日报共享次数。一次复杂操作可能先用一次识别，再用一次分析；常见查询、确认和明确指令的路由不用模型 |
| 每日估算token预留预算 | 默认200000，用于限制调用计划；按输入UTF-8字节及输出额度保守预留，五个角色会重复输入材料，多次深度研究可能耗尽。失败和取消也占用；不等于厂商实际token或账单。`/盯盘 用量`查看已用、剩余和重置时区；深度开始前检查整轮预计预算，默认额度不会自动提高 |
| 单次模型输入字符上限 | 默认24000。限制每次送入模型的消息和材料；自然语言单条输入另限制4000字，避免无限扩大上下文 |
| 请求模型单次输出token上限 | 默认2048。研判请求的输出上限，意图识别最多申请800；最终行为取决于提供商支持情况 |
| 深度角色并发上限 | 默认2，支持1～3。多角色研究时同时运行几个请求，影响速度和服务压力 |
| 深度研究总超时 | 默认300秒，支持30～900秒。一轮多角色研究的总等待时间 |

“隐藏设置总览”“我现在的大盘走向判断是什么”等常见查询直接读取数据库，不消耗模型。复杂表达需要模型识别，但程序会校验操作范围，并先展示修改草稿，不会让模型声称已经改好了。

深度研究提示整轮预算不足时，先查看 `/盯盘 用量`；可在此组提高每日估算预算，保存并重载，或等展示时区次日00:00重置。提高调用次数并不能解决估算预算不足。预检按五个角色实际输入及汇总摘要上界保守估算，不提前扣除整轮额度，实际调用逐次计入；并行的其他请求仍可能消耗预算。无需重新填写持仓或投资偏好。

每个入口保存最近三轮简短对话供补充信息，例如先说“我看多大盘”，被问到期限后再说“到今年年底”。模型只收到这些短对话、本条请求及待确认草稿等必要信息，不会因此获得行情密钥或任意宿主工具。分析流程另按原有规则发送行情、个人偏好与所选证据。

## 6. 时区与采集频率

打开「06 · 时区与采集频率」。一般保留默认。

| 设置项 | 做什么、怎么填 |
| --- | --- |
| 展示时区 | 默认 `Asia/Shanghai`，用于显示时间、日报和免打扰。美股交易日仍按纽约时区处理夏令时 |
| 免费SIP查询延迟 | 默认16分钟，最低16分钟。查询截止时间预留免费历史接口缓冲；不代表提醒恰好延迟16分钟，更不代表实时行情 |
| 单次行情请求超时 | 默认15秒，支持1～60秒。是行情HTTP请求等待时间，与AI超时不同 |
| 监控巡检间隔 | 默认300秒，支持60～3600秒。多久检查一次；缩短间隔不会消除上游数据延迟，也不会自动调用AI |
| 每轮监控及日报标的上限 | 默认5只，支持1～20。持仓优先，超出的股票会明确说明未覆盖；不是超过就自动删股 |

## 7. 先做一轮小范围试用

1. 发“隐藏设置总览”，检查空项目明确显示未设置；发“我现在的大盘走向判断是什么”，应只显示已记录的预期或明确未设置。
2. 发“关注美光，理由是等待回调”，核对草稿，回复“确认”，再查总览。只有关注变化，不能产生持仓或成交。
3. 若有实际持仓，按真实账单说明股票代码、数量和每股成本；核对草稿后确认。再查“我的持仓”。不要把文档数字当成自己的真实数据。
4. 说明自己的大盘看法和有效期限，确认后查询。用户期待与AI判断应分开；旧预期到期后不能继续冒充当前看法。
5. 发“分析一下MU”或说明具体问题，例如“看看美光今年的走势，最近回调见底了吗”。默认应先看到简报；再说“查看详细依据”检查完整证据和诊断，不需要重新调用AI。若只想定位引用问题，说“看看引用诊断”，新报告会给出字段和被拒绝引用，旧报告无法补出未记录的原文。AI提出的目标候选不应自动覆盖个人目标；采用候选仍使用 `/盯盘 目标 采用 候选ID`。
6. 按需开启监控和日报，运行推送测试，确认平台确实收到。重载后持仓、偏好与开关应保留；关闭后应停止自动推送。

自然语言一次处理一件事。修改草稿在原入口15分钟内有效；其他入口无法替你确认。期间账本、偏好或监控状态变化会使旧草稿失效。普通查询不会清除草稿；说“取消”可放弃。模型不可用或理解失败时，插件会说明未执行；可回退到 [明确指令](USAGE.md)。

## 升级、备份和手动安装

旧版配置会自动归入分组，原数据保留。聊天/原有指令修改的长期偏好和通知设置会同步到配置页；已经打开的页面需刷新，配置页改动需保存并重载。同步写入失败时会提示“记录已保存，但配置页同步失败”，此时以聊天查询的生效记录为准。

升级前用 `/盯盘 备份` 生成一致性快照，`/盯盘 备份 列表` 查看最近文件。位置是宿主插件数据目录下的 `backups/`，含持仓和报告等个人信息，不含宿主配置里的行情密钥；另备份宿主配置。不要只在运行中复制主SQLite文件而漏掉WAL。

恢复前停用插件并保留原目录，在宿主Python环境中执行：

```bash
python -m stockwatcher.maintenance inspect /safe/backup.sqlite3
python -m stockwatcher.maintenance restore /safe/backup.sqlite3 /new/place/stockwatcher.sqlite3
```

恢复不覆盖现有目标。恢复后监控和订阅暂停，需重新检查接收入口、计划及设置，再明确开启。

手动ZIP安装可使用开发目录 `dist/astrbot_plugin_stockwatcher-v0.7.5.zip`，在AstrBot插件管理上传；也可解压到 `data/plugins/astrbot_plugin_stockwatcher/`，确保 `main.py` 直接位于该目录。用同名 `.sha256` 检查完整性。ZIP不含数据库、凭证、虚拟环境或本地AstrBot参考源码，包内有源提交和逐文件哈希清单。

依赖没装成功时，在**AstrBot实际使用的Python环境**安装 `requirements.txt` 并重载。Docker部署要在对应容器环境操作。开发用 `configs/minimal.json` 只是无凭证示例，不需要另上传；复制它不会授权任何入口。

真实模型理解准确度、行情账户权限、平台主动送达和多日运行稳定性仍需在部署环境验证；离线测试不代表这些已经验收。
